# Экспериментальная загрузка системных профилей upstream

`src/system_profile_config.cpp` — эксперимент для официального upstream коммита `6d2869c430284714f0a22570c38d3b359965a802`. Он скомпилирован и слинкован с JNI для Android arm64 и прошёл одну пробную нарезку в отдельном тестовом приложении на эмуляторе Android 17 с ARM-трансляцией. Соответствие desktop и пригодность результата к печати не подтверждены; его нельзя использовать для печати. Скомпилированная версия включена в проект основного APK для экспериментального экрана; его полноценная проверка ещё не выполнена.

Вход `SystemProfileSelection`: каталог `data/system` с исходными vendor manifest JSON и деревьями профилей, точные идентификаторы vendor manifest и точные имена трёх системных пресетов: принтер, процесс и материал. Data-каталог должен быть изолированным и не содержать `user/`; все исходные деревья должны быть предварительно скопированы в `data/system`. Дополнительно нужен новый путь для записи INI. Экспериментальный JNI-вызов `sliceSystemProfiles` объединяет выбор профилей и нарезку и передаёт `full_config(false)` непосредственно в `Print::apply` в памяти, не используя INI. JNI-обёртка устанавливает ресурсный и data-каталог через API upstream и удерживает тот же глобальный mutex, который защищает `sliceStl`: настройки каталогов в движке глобальны. Экран приложения использует только путь `sliceSystemProfiles`, передающий конфигурацию непосредственно в память; старый путь через INI в экран не подключён.

Алгоритм следует публичному API upstream: `PresetBundle::load_presets(..., read_only=true)` читает `data/system`, загружает `OrcaFilamentLibrary` и vendor manifests, разрешает наследование и строит карты совместимости. Ошибки и подстановки приводят к отказу. Подбор имён строгий: профиль должен быть системным, иметь точное имя и принадлежать указанному vendor; результат выбора перепроверяется, поскольку публичный селектор может переключиться на другой профиль. После проверки совместимости выбираются все три пресета и результат формирует `PresetBundle::full_config(false)`, как в desktop-слайсинге: `Print::apply` сам разворачивает варианты экструдера и материала. После записи INI повторно загружается в пустой конфиг и сравнивается с исходным по полному набору ключей и значений; несовпадение или замены приводят к ошибке. На тестовом устройстве прежний путь с INI завершился отказом строгой проверки round-trip. Причина несовпадения ещё не диагностирована: upstream выполняет преобразования legacy при загрузке и сериализует числа с ограниченной точностью. Проверка не отключена; новый экспериментальный вызов обходит сам файл INI, передавая конфигурацию напрямую. Новый путь проверен одной пробной нарезкой официального 20-мм STL, сдвинутого на +100 мм по X/Y, с профилями Prusa CORE One 0.4 nozzle, 0.20mm SPEED @CORE One 0.4 и Prusament PLA @CORE One. Внутри тестового приложения создан непустой G-code размером 260 805 байт; в содержимом найдены заголовок upstream, 100 слоёв, команды перемещения и экструзии. Соответствие desktop ещё не проверено.

Ограничения: один экструдер FFF и один материал; другие варианты, пользовательские профили, project overrides, многоматериальная печать и отдельные bundle-варианты не поддерживаются. Подстановка несовместимых настроек отключена; частично повреждённые vendor trees и дубликаты вызывают ошибку. Официальные функции совместимости в некоторых случаях пропускают ошибочные условия как совместимые: заготовка предварительно вычисляет используемые выражения и отклоняет ошибку, но это поведение ещё требует тестирования на широком наборе профилей. Профили содержат команды G-code и параметры, зависящие от конкретного устройства: успешная проверка конфига не подтверждает безопасность полученного задания.

Экспериментальный `listSystemCompatibility` загружает системные профили в том же `PresetBundle` и использует общий с нарезкой код проверок и тот же mutex для глобальных каталогов upstream. Интерфейс передаёт отдельный приватный каталог только с vendor принтера, vendor выбранного процесса и `OrcaFilamentLibrary`: проверенный список поэтому частичен. Для материала без выбранного процесса проверяется только совместимость с принтером; ошибочные условия получают статус `unknown`. Профили других vendor в полном каталоге отмечаются непроверенными. Код скомпилирован для ARM64, но новый список ещё не проверен на устройстве и не сравнен с настольной upstream.

Для подтверждения корректности интеграции нужно расширить проверку слоя с официальным `libslic3r`, проверить наследование (включая `OrcaFilamentLibrary`), исключения материалов, разрешение переименований, отказы и результаты, сопоставить экспортированный INI и реальный G-code с настольным upstream для одинаковой модели и пресетов, а также протестировать Android thread/FP-поведение зависимостей. Текущий репозиторий не содержит доказательства этих проверок. Вызов самого `write_system_profile_ini` из нового кода должен удерживать общий mutex самостоятельно; существующая JNI-обёртка его удерживает.
